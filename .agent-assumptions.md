- **Read "improve PWA support" as "make the offline promise real."** The README already says the app "works offline as a PWA" and has a manifest, icons, and launch screen — but no service worker existed, so nothing actually worked offline. That was the biggest, most obvious gap.
- **Hand-written `public/sw.js` instead of `next-pwa`/Serwist.** Zero new dependencies, ~150 lines, and nothing to fight `next build`. Strategy: network-first navigations with cached-page then `/offline` fallback; cache-first for immutable `/_next/static/*`; stale-while-revalidate (capped at 300 entries) for sprites/artwork from the hosts already allowed in `next.config.ts`.
- **Only registered in production** (`process.env.NODE_ENV === "production"` in `src/components/pwa-register.tsx`) so the worker never intercepts HMR in `next dev`.
- **Update flow is a Sonner toast with a "Reload" action**, not a silent `skipWaiting`, so a user mid-team-edit isn't reloaded under them. The worker still calls `skipWaiting()` on first install when no controller exists.
- **Added `/offline` route** styled like `not-found.tsx` so it matches the shell; precached at install.
- **Manifest additions:** `id`, `scope`, `orientation: portrait`, `categories`, and three `shortcuts` (Cards, Teams, Favorites). `/pokemon` was skipped as a shortcut because it has no index page; `/` already is the dex.
- **No `screenshots` in the manifest** — would need real device captures the repo doesn't have.
- **Left out:** background sync, push notifications, an "install" prompt UI, and caching of API/data fetches beyond page HTML. Each is a separate feature with its own UX decisions.
- **Tests:** repo has no test runner/script, so none added. **Could not run `bun run check`** — every lint/typecheck invocation (`bun`, `bunx`, `npx`, `npm`, direct `node_modules/.bin`) was denied by the sandbox. Code was hand-checked against biome's 80-col format and the existing patterns; please run `bun run check` before merging.
